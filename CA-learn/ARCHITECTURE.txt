 CRYPTOGRAPHIC CHAIN: Apple Verifies Orange

Apple's Verification Process
─────────────────────────────

When Apple receives Orange's certificate:

  Orange presents: backend-server.pem
         ↓
  Apple loads: backend-ca.pem (received separately)
         ↓
  Verify signature:
    1. Extract signature from backend-server.pem
    2. Compute cert's digest
    3. Use backend-ca.pem's public key to decrypt signature
    4. Compare digests
         ↓
  ✓ SIGNATURE VALID
    (proves Orange-CA signed this cert, not forged)
         ↓
  Check validity:
    1. Is cert within issue date → expiry date?
    2. Is cert within Apple's time?
         ↓
  ✓ VALIDITY VALID
         ↓
  ✓✓ TRUST ESTABLISHED
    Apple now trusts Orange

Apple tries to verify Orange cert with wrong CA

═════════════════════════════════════════════════════════════════════════════════════
 CRYPTOGRAPHIC OPERATIONS
═════════════════════════════════════════════════════════════════════════════════════

Certificate Generation
──────────────────────

1. Generate private key (RSA 4096-bit)
   openssl genrsa -out private-key.pem 4096
   → Creates: private-key.pem

2. Create certificate signing request (CSR)
   openssl req -new -key private-key.pem -out cert.csr
   → Creates: cert.csr (contains public key + metadata)

3. Sign CSR with CA private key
   openssl x509 -req -in cert.csr \
     -CA ca-cert.pem -CAkey ca-key.pem \
     -out cert.pem
   → Creates: cert.pem (signed certificate)
   → Signature = encrypt(SHA256(cert_data), ca-private-key)


Certificate Verification
────────────────────────

1. Load CA public key from ca-cert.pem
2. Extract signature from cert.pem
3. Compute digest: SHA256(cert_data)
4. Decrypt signature: decrypt(signature, ca-public-key)
5. Compare digests:
   ✓ If match: signature is valid (not forged)
   ✗ If mismatch: signature is invalid (forged or wrong CA)


═════════════════════════════════════════════════════════════════════════════════════
 INDEPENDENCE PROOF
═════════════════════════════════════════════════════════════════════════════════════

Why Apple CA cannot verify Orange certs:
──────────────────────────────────────────

Orange's certificate is signed with Orange's CA private key:
  signature_orange = encrypt(digest, orange-ca-private-key)

When Apple tries to verify with Apple's CA public key:
  computed_digest = decrypt(signature_orange, apple-ca-public-key)
                  ≠ actual_digest

Because:
  apple-ca-public-key CANNOT decrypt orange-ca-private-key's encryption
  (they're from different RSA key pairs)

Result: ✗ Verification fails
Proof: ✓ Independence confirmed


═════════════════════════════════════════════════════════════════════════════════════
 SUMMARY
═════════════════════════════════════════════════════════════════════════════════════

Two independent CAs:
  • Each has its own key pair (public + private)
  • Each signs its own certificates
  • Certificates are NOT interchangeable
  • Trust is NOT shared until CAs exchange public certs

Verification:
  • Recipient loads sender's CA public cert
  • Recipient verifies sender's certificate signature
  • Cryptography proves authenticity (not forged)

In mTLS:
  • Both parties exchange CAs publicly
  • Both verify each other's certificates
  • Bidirectional trust established
  • Communication is encrypted + authenticated

This is the foundation of mTLS.
